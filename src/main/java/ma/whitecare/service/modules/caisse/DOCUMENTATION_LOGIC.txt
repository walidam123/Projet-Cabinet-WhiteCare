1. ARCHITECTURE GÉNÉRALE
═══════════════════════════════════════════════════════════════════════════════

L'application suit une architecture en couches (Layered Architecture) :

┌─────────────────────────────────────────────────────────────┐
│                    COUCHE PRÉSENTATION (MVC)                │
│              (Interface utilisateur - Swing)                 │
└───────────────────────┬─────────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────────┐
│                    COUCHE SERVICE                           │
│         (Logique métier + Validation)                        │
│  - ChargesService / RevenuesService                         │
└───────────────────────┬─────────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────────┐
│                    COUCHE REPOSITORY                         │
│            (Accès aux données - JDBC)                       │
│  - ChargesRepository / RevenuesRepository                   │
└───────────────────────┬─────────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────────┐
│                    BASE DE DONNÉES (MySQL)                  │
│              Tables: charges, revenues                      │
└─────────────────────────────────────────────────────────────┘

PRINCIPE : Chaque couche ne communique qu'avec la couche inférieure
           (Dependency Inversion Principle - DIP)

3. VALIDATEURS (VALIDATORS)
═══════════════════════════════════════════════════════════════════════════════

📁 Fichier: src/main/java/ma/whitecare/common/validators/ChargesValidator.java
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ROLE:
    Valide les données d'une charge avant leur traitement.

MÉTHODES PRINCIPALES:

1. validateCharge(Charges charge) → List<String>
   - Retourne une liste d'erreurs de validation
   - Vérifie: titre, description, montant, date, cabinetId
   - Utilisée pour collecter toutes les erreurs avant de les lever

2. validateChargeForUpdate(Charges charge) → List<String>
   - Même validation + vérification de l'ID
   - L'ID est obligatoire pour une mise à jour

3. validateChargeOrThrow(Charges charge) → void
   - Valide et lève InvalidChargeException si erreurs
   - Utilisée dans les services pour validation rapide

4. validateChargeForUpdateOrThrow(Charges charge) → void
   - Valide pour mise à jour et lève exception si erreurs

RÈGLES DE VALIDATION:
    ✓ Titre: 3-100 caractères, obligatoire
    ✓ Description: max 255 caractères (optionnelle)
    ✓ Montant: > 0, max 999 999 999.99
    ✓ Date: non nulle, pas dans le futur
    ✓ CabinetId: positif, obligatoire

EXEMPLE D'UTILISATION:
    // Dans le service
    ChargesValidator.validateChargeOrThrow(charge);
    // Si erreur → InvalidChargeException levée automatiquement

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FONCTIONNEMENT:

   Connection c = SessionFactory.getInstance().getConnection();
   // SessionFactory gère le pool de connexions

2. EXÉCUTION DES REQUÊTES:
   - Utilise PreparedStatement pour éviter les injections SQL
   - Utilise RowMappers pour convertir ResultSet → Entité

3. EXEMPLE (create):
   String sql = "INSERT INTO charges (titre, description, montant, date, ...) 
                 VALUES (?, ?, ?, ?, ...)";
   PreparedStatement ps = c.prepareStatement(sql, RETURN_GENERATED_KEYS);
   ps.setString(1, charge.getTitre());
   ps.setDouble(3, charge.getMontant());
   // ...
   ps.executeUpdate();
   // Récupère l'ID généré
   ResultSet rs = ps.getGeneratedKeys();
   if (rs.next()) charge.setId(rs.getLong(1));

4. GESTION DES ERREURS:
   catch (SQLException e) { throw new RuntimeException(e); }

   │ 2. Vérification existence du cabinet                   │
   │    → Lève CabinetNotFoundException si inexistant       │
   ├─────────────────────────────────────────────────────────┤
   │ 3. Création via repository                             │
   │    chargesRepository.create(charge)                     │
   ├─────────────────────────────────────────────────────────┤
   │ 4. Retour de la charge avec ID généré                  │
   └─────────────────────────────────────────────────────────┘

2. GET BY ID:
   ┌─────────────────────────────────────────────────────────┐
   │ 1. Validation ID (positif)                           │
   │    → Lève InvalidChargeException si invalide           │
   ├─────────────────────────────────────────────────────────┤
   │ 2. Recherche via repository                            │
   │    Charges charge = chargesRepository.findById(id)     │
   ├─────────────────────────────────────────────────────────┤
   │ 3. Vérification existence                              │
   │    → Lève ChargesNotFoundException si null             │
   ├─────────────────────────────────────────────────────────┤
   │ 4. Retour de la charge                                 │
   └─────────────────────────────────────────────────────────┘

3. UPDATE CHARGE:
   ┌─────────────────────────────────────────────────────────┐
   │ 1. Validation pour mise à jour                        │
   │    (inclut vérification ID)                            │
   ├─────────────────────────────────────────────────────────┤
   │ 2. Vérification existence charge                       │
   │    getChargeById(charge.getId())                       │
   ├─────────────────────────────────────────────────────────┤
   │ 3. Si cabinetId modifié, vérifier nouveau cabinet     │
   ├─────────────────────────────────────────────────────────┤
   │ 4. Mise à jour via repository                          │
   │    chargesRepository.update(charge)                    │
   └─────────────────────────────────────────────────────────┘

4. DELETE CHARGE:
   ┌─────────────────────────────────────────────────────────┐
   │ 1. Vérification existence (getChargeById)              │
   ├─────────────────────────────────────────────────────────┤
   │ 2. Suppression via repository                          │
   │    chargesRepository.deleteById(id)                    │
   └─────────────────────────────────────────────────────────┘

5. CALCULATIONS:
   ┌─────────────────────────────────────────────────────────┐
   │ 1. Validation cabinetId                                │
   ├─────────────────────────────────────────────────────────┤
   │ 2. Validation plage de dates (si applicable)          │
   │    → startDate < endDate                                │
   ├─────────────────────────────────────────────────────────┤
   │ 3. Appel repository pour calcul                         │
   │    Double total = repository.calculateTotal(...)      │
   ├─────────────────────────────────────────────────────────┤
   │ 4. Retour (0.0 si null)                                │
   └─────────────────────────────────────────────────────────┘

MÉTHODES PRIVÉES (Helpers):
    - validateCabinetExists(Long cabinetId)
      → Vérifie l'existence et la validité du cabinet
    
    - validateDateRange(LocalDateTime start, LocalDateTime end)
      → Vérifie que start < end et que les dates sont non nulles
